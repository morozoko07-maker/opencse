1.2

Advantages of the database approach

  • Controls redundancy — one shared copy, less inconsistency.
  • Restricts unauthorised access — central security.
  • Enforces integrity constraints — keys and rules in one place.
  • Provides backup and recovery.
  • Supports multiple views and interfaces.
  • Efficient query processing — indexes, optimisation.
  • Represents complex relationships and supports concurrent users.
1.3

Characteristics of the database approach ★

  1. Self-describing: the catalog stores metadata, so the DBMS can work with different databases.
  2. Program–data independence: change storage/structure without rewriting programs.
  3. Data abstraction: a data model hides physical storage details.
  4. Multiple views: each user sees only the data of interest.
  5. Sharing and multi-user transaction processing: concurrency control + recovery; supports OLTP.
Memory: Self-describing · Insulation · Abstraction · Multiple views · Sharing.

Users of a DBMS

Actors on the scene
  • DBA — authorises access, monitors use, backup/recovery, tuning.
  • Database designer — defines structure, constraints and transactions.
  • End users — casual, naïve/parametric (bank teller), sophisticated (analyst), stand-alone.
Workers behind the scene
  • DBMS designers/implementers.
  • Tool developers.
  • Operators and maintenance staff.

Logical data independence: change the conceptual schema without changing external views or programs.

DBMS languages

  • DDL — defines the schema: CREATE, ALTER, DROP.

1.8

COMPANY ER diagram ★

Six relationships: WORKS_FOR (N:1), MANAGES (1:1), CONTROLS (1:N), WORKS_ON (M:N, with Hours), SUPERVISION (recursive 1:N), DEPENDENTS_OF (weak, 1:N).

1.9

ER → relational schema

  • Strong entity → table; choose the key; flatten composite attributes.
  • 1:N → put the “1” side's key as a foreign key on the “N” side.
  • M:N → new table with both keys + relationship attributes; composite PK.
  • 1:1 → foreign key on the total-participation side, with UNIQUE.
  • Weak entity → table with owner key + partial key; composite PK.
  • Multi-valued attribute → separate table with owner key + value.
SCHEMA · COMPANY
EMPLOYEE(SSN, Name, Address, Gender, Salary, SuperSSN, Dno)
DEPARTMENT(Dno, Dname, MgrSSN, MgrStartDate)
DLOCATION(Dno, Dloc)
PROJECT(Pno, Pname, Plocation, Dno)
WORKS_ON(SSN, Pno, Hours)
DEPENDENT(Essn, Name, Gender, Bdate, Relationship)

PKs: SSN · Dno · (Dno,Dloc) · Pno · (SSN,Pno) · (Essn,Name). FKs: SuperSSN→EMPLOYEE, Dno→DEPARTMENT, MgrSSN→EMPLOYEE, Essn→EMPLOYEE.

1.10

Query processing steps ★

  1. User query — SQL entered at an interface.
  2. Parser — checks syntax and builds a parse tree.
  3. Translator — converts SQL to relational algebra.
  4. Optimiser — picks the lowest-cost execution plan (index scan vs full scan).
  5. Execution engine — runs the plan.
  6. Storage manager — file manager, buffer manager, index manager fetch data.
  7. Database — returns the result.
Diagram: SQL → Parser → Translator → Optimiser → Execution → Storage manager → Database.

4.1

Types: INT, DECIMAL(p,s), CHAR(n), VARCHAR(n), DATE, TIME, TIMESTAMP, BLOB/CLOB. Oracle: NUMBER, VARCHAR2.

4.2

CREATE TABLE + constraints ★

SQL · constraints
CREATE TABLE EMPLOYEE (
  SSN       CHAR(9) PRIMARY KEY,
  Name      VARCHAR(50) NOT NULL,
  Gender    CHAR(1) CHECK (Gender IN ('M','F')),
  Salary    DECIMAL(10,2) CHECK (Salary >= 0),
  SuperSSN  CHAR(9),
  Dno       INT NOT NULL,
  CONSTRAINT fk_super FOREIGN KEY (SuperSSN) REFERENCES EMPLOYEE(SSN),
  CONSTRAINT fk_dept  FOREIGN KEY (Dno) REFERENCES DEPARTMENT(Dno)
);
  • PRIMARY KEY = unique + NOT NULL; one per table.
  • FOREIGN KEY = value must exist in the parent key (or be NULL).
  • UNIQUE = no duplicates; NULLs may be allowed.
  • CHECK = row-level condition; cannot query other tables.
  • ON DELETE CASCADE / SET NULL / RESTRICT = what happens to child rows.
4.3

ALTER, DROP, TRUNCATE

SQL · schema changes
ALTER TABLE EMPLOYEE ADD Email VARCHAR(100);
ALTER TABLE EMPLOYEE RENAME COLUMN Address TO Addr;  -- Oracle
ALTER TABLE EMPLOYEE DROP COLUMN Email;

DROP TABLE EMPLOYEE;          -- removes table + data
TRUNCATE TABLE EMPLOYEE;      -- removes all rows, keeps table

DELETE = DML, can roll back, fires row triggers. TRUNCATE = DDL, fast, usually no rollback. DROP = removes the table definition.

4.4

INSERT / UPDATE / DELETE

SQL · DML
INSERT INTO EMPLOYEE (SSN, Name, Salary, Dno)
VALUES ('111111111', 'Priya', 31000, 5);

UPDATE EMPLOYEE
SET Salary = Salary * 1.10
WHERE Dno = 5;

DELETE FROM EMPLOYEE
WHERE SSN = '111111111';

Omitted columns get DEFAULT or NULL. Missing WHERE changes every row.

4.5

SELECT — order of writing vs order of evaluation ★

SQL · skeleton
SELECT   [DISTINCT] columns
FROM     tables
[WHERE   row_condition]
[GROUP BY columns]
[HAVING  group_condition]
[ORDER BY columns [ASC|DESC]]
[LIMIT n];

Evaluation order: FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT.

That is why an alias cannot be used in WHERE, and aggregates go in HAVING.

SQL · filters
SELECT Name, Salary
FROM EMPLOYEE
WHERE Dno = 5
  AND Salary BETWEEN 30000 AND 40000
ORDER BY Salary DESC;
4.6

Aggregates, GROUP BY, HAVING ★

FunctionReturnsNULL?
COUNT(*)RowsCounts all rows
COUNT(col)Non-NULL valuesIgnores NULL
SUM, AVGTotal / meanIgnores NULL
MIN, MAXSmallest / largestIgnores NULL
SQL · per department
SELECT Dno,
       COUNT(*) AS Employees,
       AVG(Salary) AS Avg_Salary
FROM EMPLOYEE
GROUP BY Dno
HAVING COUNT(*) > 2;

WHERE filters rows before grouping; HAVING filters groups after grouping.

4.7

Joins

SQL · employee + department + project
SELECT E.Name, D.Dname, P.Pname, W.Hours
FROM EMPLOYEE E
JOIN DEPARTMENT D ON E.Dno = D.Dno
JOIN WORKS_ON W  ON E.SSN = W.SSN
JOIN PROJECT P    ON W.Pno = P.Pno
WHERE P.Pname = 'ProductX';
  • INNER JOIN — only matching rows.
  • LEFT JOIN — all left rows; NULLs if no match.
  • Self join — same table twice with aliases (employee/supervisor).
  • Cartesian product — join condition missing.
SQL · self join
SELECT E.Name AS Employee, S.Name AS Supervisor
FROM EMPLOYEE E
LEFT JOIN EMPLOYEE S ON E.SuperSSN = S.SSN;
4.8

Subqueries & EXISTS ★

SQL · above average / no dependents / second highest
SELECT Name FROM EMPLOYEE
WHERE Salary > (SELECT AVG(Salary) FROM EMPLOYEE);

SELECT Name FROM EMPLOYEE E
WHERE NOT EXISTS (
  SELECT 1 FROM DEPENDENT D WHERE D.Essn = E.SSN
);

SELECT MAX(Salary) FROM EMPLOYEE
WHERE Salary < (SELECT MAX(Salary) FROM EMPLOYEE);

IN compares values; EXISTS tests whether a row exists. Prefer NOT EXISTS over NOT IN when NULLs may appear.

4.9

Views

SQL · view
CREATE VIEW HighEarners AS
SELECT SSN, Name, Salary, Dno
FROM EMPLOYEE
WHERE Salary > 40000;

DROP VIEW HighEarners;

Benefits: security (hide columns/rows), simplicity, logical data independence, customised presentation. A view on one table with its key can be updatable; DISTINCT, GROUP BY and aggregates make it read-only.

4.10

Assertions ★

SQL · manager salary check
CREATE ASSERTION Manager_Salary_Check
CHECK (
  NOT EXISTS (
    SELECT *
    FROM EMPLOYEE E, DEPARTMENT D
    WHERE E.Dno = D.Dno
      AND D.MgrSSN = E.SuperSSN
      AND E.Salary >= (
        SELECT Salary FROM EMPLOYEE WHERE SSN = D.MgrSSN
      )
  )
);

Meaning: there is no employee supervised by the department manager who earns at least the manager's salary. If no such row exists, the assertion holds.

Standard SQL; Oracle does not support CREATE ASSERTION — use a trigger in practice.

4.11

Triggers ★

Oracle PL/SQL · salary audit
CREATE OR REPLACE TRIGGER salary_audit
AFTER INSERT OR UPDATE OR DELETE ON EMPLOYEE
FOR EACH ROW
BEGIN
  IF INSERTING THEN
     DBMS_OUTPUT.PUT_LINE('New Salary: ' || :NEW.Salary);
  ELSIF UPDATING THEN
     DBMS_OUTPUT.PUT_LINE('Old Salary: ' || :OLD.Salary);
     DBMS_OUTPUT.PUT_LINE('New Salary: ' || :NEW.Salary);
     DBMS_OUTPUT.PUT_LINE('Difference: ' || (:NEW.Salary - :OLD.Salary));
  ELSIF DELETING THEN
     DBMS_OUTPUT.PUT_LINE('Deleted Salary: ' || :OLD.Salary);
  END IF;
END;
/
  • Row-level (FOR EACH ROW) fires once per row; statement-level once per statement.
  • :OLD = value before; :NEW = value after.
  • INSERT has NEW only; DELETE has OLD only; UPDATE has both.
  • Use for audit, complex constraints, derived values; avoid mutating-table errors.
4.12

Privileges

SQL · grant / revoke
CREATE USER dbms_user IDENTIFIED BY dbms123;
GRANT ALL PRIVILEGES TO dbms_user;
GRANT SELECT, INSERT ON EMPLOYEE TO dbms_user;
REVOKE INSERT ON EMPLOYEE FROM dbms_user;

COMPANY queries to memorise

These cover almost every SQL question in the paper. Learn the pattern, not the exact wording.

1. Employees working on more than 3 projects

SELECT E.SSN, E.Name, COUNT(W.Pno) AS Projects
FROM EMPLOYEE E
JOIN WORKS_ON W ON E.SSN = W.SSN
GROUP BY E.SSN, E.Name
HAVING COUNT(W.Pno) > 3;

2. Employees with no dependents

SELECT Name FROM EMPLOYEE E
WHERE NOT EXISTS (
  SELECT 1 FROM DEPENDENT D WHERE D.Essn = E.SSN
);

3. Employees born in the 1950s

SELECT Name FROM EMPLOYEE
WHERE Bdate LIKE '195%';

Safer date version: Bdate >= DATE '1950-01-01' AND Bdate < DATE '1960-01-01'.

4. Salary total, max, min, average

SELECT SUM(Salary) AS Total, MAX(Salary) AS Max,
       MIN(Salary) AS Min, AVG(Salary) AS Avg
FROM EMPLOYEE;

5. Projects involving “Smith”

SELECT Pno FROM PROJECT
WHERE Dno IN (
  SELECT Dno FROM DEPARTMENT
  WHERE MgrSSN IN (SELECT SSN FROM EMPLOYEE WHERE Name='Smith')
)
OR Pno IN (
  SELECT Pno FROM WORKS_ON
  WHERE SSN IN (SELECT SSN FROM EMPLOYEE WHERE Name='Smith')
);

6. Number of employees per department

SELECT Dno, COUNT(*) AS Employees
FROM EMPLOYEE
GROUP BY Dno;

7. Employees whose address contains “Hyderabad”

SELECT * FROM EMPLOYEE
WHERE Address LIKE '%Hyderabad%';

8. Dept 5 employees earning 30000–40000

SELECT * FROM EMPLOYEE
WHERE Dno = 5 AND Salary BETWEEN 30000 AND 40000;

9. Employee name with department name

SELECT E.Name, D.Dname
FROM EMPLOYEE E
JOIN DEPARTMENT D ON E.Dno = D.Dno;

10. Employee, project and hours

SELECT E.Name, P.Pname, W.Hours
FROM EMPLOYEE E
JOIN WORKS_ON W ON E.SSN = W.SSN
JOIN PROJECT P ON W.Pno = P.Pno;

11. Employees earning above the company average

SELECT Name, Salary FROM EMPLOYEE
WHERE Salary > (SELECT AVG(Salary) FROM EMPLOYEE);

12. Second-highest salary

SELECT MAX(Salary) AS Second_Highest
FROM EMPLOYEE
WHERE Salary < (SELECT MAX(Salary) FROM EMPLOYEE);

13. Employees with no project

SELECT E.Name FROM EMPLOYEE E
WHERE NOT EXISTS (
  SELECT 1 FROM WORKS_ON W WHERE W.SSN = E.SSN
);

14. Department with the highest average salary

SELECT Dno, AVG(Salary) AS Avg_Salary
FROM EMPLOYEE
GROUP BY Dno
HAVING AVG(Salary) >= ALL (
  SELECT AVG(Salary) FROM EMPLOYEE GROUP BY Dno
);

15. Raise salary by 10% in department 5

UPDATE EMPLOYEE
SET Salary = Salary * 1.10
WHERE Dno = 5;
Query pattern: “more than N” → JOIN + GROUP BY + HAVING · “none” → NOT EXISTS · “all” → double NOT EXISTS · “above average” → subquery with AVG · “same as X” → nested IN.

2-mark definitions

01Define data, database, DBMS and database system.

Data: recorded facts with implicit meaning. Database: collection of related data. DBMS: software to define, construct, manipulate and share a database. Database system: DBMS + data (+ applications).

02Differentiate schema and instance.

Schema = description of the database (intension); changes rarely. Instance = actual data at a moment (extension); changes on every update. Example: STUDENT(ID, Name, Age) vs the current rows.

03What is metadata?

Data about data — the description of structures, types and constraints stored in the DBMS catalog. It makes the database self-describing.

04Differentiate DDL and DML.

DDL defines/changes the schema (CREATE, ALTER, DROP). DML manipulates data (SELECT, INSERT, UPDATE, DELETE).

05Differentiate logical and physical data independence.

Logical: change the conceptual schema without changing external views/programs. Physical: change the internal schema without changing the conceptual schema.

06Define entity, attribute and entity set.

Entity: object in the mini-world. Attribute: property of an entity. Entity set: current collection of entities of one type.

07What is a weak entity?

An entity with no key of its own; identified by a partial key plus its owner through an identifying relationship. Example: DEPENDENT, identified by (Essn, Name).

08Differentiate cardinality and participation.

Cardinality = maximum participation (1:1, 1:N, M:N). Participation = minimum: total (1, double line) or partial (0, single line).

09Differentiate primary key and foreign key.

Primary key uniquely identifies a row and cannot be NULL. Foreign key references a primary key in another table (or the same table), enforcing referential integrity.

10Differentiate DELETE, TRUNCATE and DROP.

DELETE = DML, removes selected rows, can roll back. TRUNCATE = DDL, removes all rows, keeps the table, usually no rollback. DROP = removes the table definition and data.

11Differentiate WHERE and HAVING.

WHERE filters rows before grouping and cannot contain aggregates. HAVING filters groups after GROUP BY and usually contains aggregates.

12Differentiate COUNT(*) and COUNT(column).

COUNT(*) counts all rows. COUNT(col) counts non-NULL values only.

5 / 7-mark questions

13Explain the characteristics of the database approach.

Self-describing catalog; program–data independence; data abstraction; multiple views; sharing plus concurrency control and recovery (OLTP).

14Explain the three-schema architecture with a diagram.

External (user views), conceptual (whole logical database) and internal (physical storage/indexes) levels, joined by logical and physical mappings. Supports data independence and multiple views.

15Explain the users of a DBMS.

Actors on the scene: DBA, database designers, end users (casual, naïve/parametric, sophisticated, stand-alone). Workers behind the scene: DBMS designers, tool developers, operators.

16Draw the COMPANY ER diagram and explain its relationships.

EMPLOYEE, DEPARTMENT, PROJECT, weak DEPENDENT. WORKS_FOR N:1, MANAGES 1:1, CONTROLS 1:N, WORKS_ON M:N with Hours, SUPERVISION recursive 1:N, DEPENDENTS_OF identifying relationship.

17Explain weak entity types with the DEPENDENT example.

DEPENDENT has no key of its own. Partial key Name + owner Essn identifies it. Double rectangle, double diamond and dashed underline are the notation. Relational key is (Essn, Name).

18Explain ER-to-relational mapping.

Strong entity → table; 1:N → FK on N side; M:N → new table with both keys + attributes; weak entity → owner key + partial key; multi-valued attribute → separate table.

19Explain the steps in query processing.

SQL → parser → translator (relational algebra) → optimiser → execution engine → storage manager (file/buffer/index) → database.

20Explain the types of joins.

Inner/equi, theta, natural, cross, left/right/full outer, and self join. Inner returns matches; outer keeps unmatched rows with NULLs.

21What is a view? State its advantages.

A stored query / virtual table. Advantages: security, simplicity, logical data independence, customised presentation.

22Explain triggers and their parts.

Fires on INSERT/UPDATE/DELETE; BEFORE/AFTER/INSTEAD OF; row or statement level; optional WHEN; uses OLD/NEW. Used for audit, complex constraints and derived values.

SQL traps / short answers

38Why does NOT IN fail with NULLs?

If the subquery returns NULL, x <> NULL is UNKNOWN for every row, so the result is empty. Use NOT EXISTS.

39What does NULL mean? How do you test it?

Unknown/not applicable. Use IS NULL / IS NOT NULL; = NULL is UNKNOWN. Aggregates ignore NULL except COUNT(*).

40Differentiate assertion and trigger.

Assertion = schema-level boolean condition, can span tables; standard SQL but poorly supported. Trigger = procedural code fired by an event; widely supported.

41What are :OLD and :NEW?

Row values before and after the event. INSERT has NEW only; DELETE has OLD only; UPDATE has both.

42Which views are updatable?

Generally a single-table view that includes the key and has no DISTINCT, GROUP BY, aggregate or UNION.

43What does ON DELETE CASCADE do?

Deletes child rows automatically when the parent row is deleted. Example: deleting an employee deletes their dependents.

44State the GROUP BY rule.

Every SELECT expression must be an aggregate or a GROUP BY column. WHERE filters rows; HAVING filters groups.

45Differentiate correlated and uncorrelated subqueries.

Uncorrelated: independent, evaluated once. Correlated: references the outer row and is evaluated per outer row (e.g. department average).

The five characteristics:

  1. Self-describing: catalog stores metadata; DBMS works with different databases.
  2. Program–data independence: change structure/storage without rewriting programs.
  3. Data abstraction: data model hides physical storage.
  4. Multiple views: each user sees only relevant data.
  5. Sharing + multi-user processing: concurrency control and recovery; supports OLTP.

SchemaInstance
Description/structure of the databaseActual data at a moment
Changes rarely; intensionChanges every update; extension
Like a blank formLike a filled form

Q3 · DDL and DML 10 M

DDL (5): defines structure.

CREATE TABLE Students (ID INT PRIMARY KEY, Name VARCHAR(50));
ALTER TABLE Students ADD Email VARCHAR(100);
DROP TABLE Students;

DML (5): manipulates data.

INSERT INTO Students VALUES (101, 'Alex');
UPDATE Students SET Name='Alexa' WHERE ID=101;
DELETE FROM Students WHERE ID=101;

Q4 · Steps in query processing 10 M

  1. User writes SQL.
  2. Parser checks syntax; parse tree.
  3. Translator → relational algebra.
  4. Optimiser chooses the cheapest plan.
  5. Execution engine runs the plan.
  6. Storage manager (file/buffer/index) fetches data from the database.

Diagram: SQL → Parser → Translator → Optimiser → Execution → Storage Manager → Database.

(iv) Dept 5, salary 30000–40000: SELECT * FROM EMPLOYEE WHERE Dno=5 AND Salary BETWEEN 30000 AND 40000;

Q7 · Trigger 10 M

CREATE OR REPLACE TRIGGER salary_audit
AFTER INSERT OR UPDATE OR DELETE ON EMPLOYEE
FOR EACH ROW
BEGIN
  IF INSERTING THEN
     DBMS_OUTPUT.PUT_LINE('New Salary: ' || :NEW.Salary);
  ELSIF UPDATING THEN
     DBMS_OUTPUT.PUT_LINE('Old Salary: ' || :OLD.Salary);
     DBMS_OUTPUT.PUT_LINE('New Salary: ' || :NEW.Salary);
     DBMS_OUTPUT.PUT_LINE('Difference: ' || (:NEW.Salary - :OLD.Salary));
  ELSIF DELETING THEN
     DBMS_OUTPUT.PUT_LINE('Deleted Salary: ' || :OLD.Salary);
  END IF;
END;
/

Explanation: row-level trigger fires per row; :OLD/:NEW hold before/after values; INSERT uses NEW, DELETE uses OLD, UPDATE uses both.

Q8 · Assertion 10 M

CREATE ASSERTION Manager_Salary_Check
CHECK (NOT EXISTS (
  SELECT * FROM EMPLOYEE E, DEPARTMENT D
  WHERE E.Dno=D.Dno AND D.MgrSSN=E.SuperSSN
    AND E.Salary >= (
      SELECT Salary FROM EMPLOYEE WHERE SSN=D.MgrSSN
    )
));

Explanation: finds an employee supervised by the department manager who earns at least the manager's salary. If none exists, the assertion holds.

Oracle doesn't support assertions; use a trigger in the lab.
