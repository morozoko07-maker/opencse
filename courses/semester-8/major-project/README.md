# Major Project

The eighth semester is the project. There is no written paper here, so the
marks come from the process, the demonstration and the report.

## How the marks usually fall

Confirm the split with your guide, but the shape is normally:

| Component | What is judged |
|---|---|
| Problem definition | Is the problem real, scoped and stated without padding? |
| Literature survey | Recent, relevant, and actually read — not a list of titles. |
| Design | Alternatives considered, choices justified. |
| Implementation | It runs, and you can explain the parts you did not write. |
| Report | Structure, figures, references, formatting. |
| Viva | You defend the work without notes. |

## Suggested rhythm

1. **Weeks 1–3** — freeze the problem statement. One paragraph, one measurable
   outcome. Get it signed off early; changing later costs the most time.
2. **Weeks 4–6** — survey and baseline. Reproduce one existing result so you
   know your data and metrics are honest.
3. **Weeks 7–11** — build the smallest complete version. Keep a running log of
   what failed; it becomes the evaluation section.
4. **Weeks 12–14** — evaluate, then write. Draft the report while results are
   fresh, not in the last week.
5. **Final week** — rehearse the demo twice on the machine you will present on.
   Keep a recorded fallback.

## Report skeleton

- Abstract (200 words, results included)
- Introduction and motivation
- Literature survey
- Problem statement and objectives
- Methodology / design
- Implementation
- Results and discussion (tables, graphs, failure cases)
- Conclusion and future work
- References (consistent style)

## What belongs in this folder

Put the report, presentation, poster, code archive and any datasets you are
allowed to share under `material/`. Keep large datasets out of git — link them
instead.
